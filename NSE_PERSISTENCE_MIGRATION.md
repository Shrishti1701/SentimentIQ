# NSE announcement persistence schema change

**Prepared before changing ORM metadata.** The additive ORM model described below is now present for synthetic tests. No migration has been applied to a configured application database. Any later approved NSE ingestion still requires a reviewed production migration.

## Why the existing schema is insufficient

`FinancialArticle` already provides the appropriate article row: its `source_url` is required and unique, `source_name` identifies the source, `original_text` is required, `published_at` is nullable, and `collected_at` is generated by the database. It cannot retain the source title, the exact timestamp string, the parsed unzoned wall time, or the parser's identity key/method. `published_at` must remain NULL until NSE confirms timestamp semantics.

Linkless fallback identities cannot be stored as `FinancialArticle` records because `source_url` is non-null and no synthetic URL should be invented. The persistence layer will therefore reject linkless records even when the parser generated its lower-confidence fallback identity.

## Additive ORM table and required production migration

Add a one-to-one `nse_announcement_metadata` table referencing `financial_articles.id`:

| Column | Type | Constraints/purpose |
|---|---|---|
| `id` | Integer | Primary key |
| `article_id` | Integer | Non-null FK to `financial_articles.id`, unique |
| `source_item_key` | String(100) | Non-null, unique cross-poll deduplication key |
| `identity_method` | String(20) | Non-null (`url` for persistable records) |
| `source_title` | String(300) | Nullable original RSS title |
| `published_at_raw` | String(100) | Nullable exact source timestamp text |
| `published_at_unzoned` | DateTime without timezone | Nullable naive wall time; explicitly not UTC or IST |
| `timezone_status` | String(30) | Non-null; defaults to `unknown` |

This is additive: it does not alter existing article, company, aspect, or prediction columns/constraints. The existing `FinancialArticle.source_url` unique constraint remains in force. No source summary/raw feed payload table is proposed; the synthetic adapter uses the existing required `original_text` field for its supplied summary. Retaining genuine NSE summaries remains subject to written permission.

## Application and rollback

The repository currently has no migration framework or revision history. Do not use `Base.metadata.create_all()` against a configured application database as a substitute for a reviewed production migration. For isolated SQLite tests, create the metadata on a fresh in-memory database. Before any production schema application, add an explicit, reviewed SQL migration (create table, FK, unique constraints; reverse by dropping the new table), test it against the target database, and apply it only after the NSE storage permission is confirmed.

The `NSEAnnouncementMetadata` ORM model describes this table for isolated SQLite tests. This document does not claim that the table exists in any deployed database.
